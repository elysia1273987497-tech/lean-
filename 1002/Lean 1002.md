# <h2 id=chapter1>语法（基础知识）</h2>
- 类型
 lean中定义函数一般要求写出定义域，值域的类型
eg：
  >#check 1 -> Nat
  #check 1.0 -> Float
  类型非常多样例如 x : |x-x_o| < /e 也可以作为一种类型
- 柯里化：f（x,y）的类型为x的类型->y的类型->值域的类型
   eg:
  >平方函数：nat->nat

- 如何定义函数
eg:
  >def mul (n : Nat) (m:Nat) : Nat:=n*m
  #def 'name' '定义域类型' '定义域类型' '值域类型' '具体公式'
- 高阶函数：函数作为参数，返回值可以为函数
eg:
>def sum_of_powers (power : Nat -> Nat) (a : Nat) (b : Nat) : Nat := power a + power b
- 右结合原则
  eg:
>Nat->Nat->Nat->Nat相当于Nat->(Nat->(Nat->Nat))(每次可以在最右边加上括号)
- 条件分支
一般公式 if_then else
> eg:绝对值函数
- 模式匹配（类似归纳定义）（递归）
  match n with
  也可以用termination_by 直接声明终止度量（这样就需要严格证明）
- 尾递归（函数在调用自身后就不会有什么操作了）
传统递归会面临一些问题：每一步依赖于前一步，内存空间可能会不够（栈溢出/爆栈）
希望式子不随着n变大而变长
一种做法是在中途创立一个新的辅助函数
eg：
>def fact_aux (n : Nat) (acc : Nat) : Nat :=
  match n with
  |0 => acc
  |k + 1 => fact_aux k ((k+1) * acc)
  
  这里每一步都是数组到数组的变化（5，1）=>(4,5)=>(3,20)=>(2,60)=>(1,120)=>(0,120)
  所以相当于把一个庞大的计算分解成为了若干小的计算，这样能使计算机同时需要做的计算量小得多
- 命名空间：一般情况下是默认/总命名空间
 创建一个子命名空间：namespace 'name'在命名空间内无需调用，命名空间外需要调用（说实话感觉用处不大？）



# <h2 id=chapter2>数学相关</h2>
- mathlib4（数学库，大量已经验证过的定理/内容）
- 一些相关代码
example：声明一个命题
   - intro：把目标里的/all或者/to搬到假设里
  > ⊢ P → Q → R 经过 intro hp后会变成：
hp ： P  ⊢Q → R

  - obtain ：「按 h 的类型结构，把它的组成部分提取出来」。组成部分可能是值、可能是命题的证明、也可能是另一个结构。
   > obtain<h1 , h2> := h(从此不再有h)
  - use 给一个见证，类似于（补充证据）
  - apply :欲证某个东西，只需证
  >h : P → Q 使用apply h 后变成：|-P
  -rw（不含逻辑，仅仅改写形式）
 
- 柯里-霍华德同构
逻辑，类型，计算类存在对应关系
命题即类型，证明即项
一个命题为真当且仅当能在有限步内构造出证明（有点哲学的感觉？）
任何一个命题都可以被转化为证明一个东西的存在性（？）
